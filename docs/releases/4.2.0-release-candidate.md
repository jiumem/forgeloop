# Forgeloop 4.2.0 发布候选

状态：源码门禁与本地候选安装回读已通过，且已取得创建 Release PR、合并、Tag 和 GitHub Release 的明确授权。只能从 Release PR 合并后的最终 `main` Commit 发布。

## 发布范围

- 恢复 `spec-standards-review` 的上游固定点变更审查 description，明确双轴并行 Reviewer 的适用范围与成本；
- 保留 `run-initiative` 在冻结 Candidate Base/Head 后自动创建双 Reviewer 的交付门禁；
- 取消 Forgeloop 对所有 Skill description 必须以 `Load when` 开头且不超过 240 字符的本地限制，使集中元数据可以忠实承载上游审查契约；
- 将 Manifest、README 与发布配置升级为 `4.2.0`。

## 验收标准

- 入口：Manifest、README 和发布配置统一回读为 `4.2.0`；
- 核心行为：PR、`review since` 与冻结 Candidate Commit 范围加载双轴审查；普通实现自检和无审查请求的单文件检查不加载；
- 输出状态：上游同步与 Skill UI 元数据从集中配置生成一致结果；
- 错误处理：描述为空、多行、与集中元数据漂移，或安装缓存版本漂移时，验证必须失败并给出可定位输出；
- 关键边界：不关闭 `spec-standards-review` 的隐式调用，不影响 `run-initiative` 的双 Reviewer 门禁，不新增运行时状态；
- 发布验证：Release PR 合并后，Tag、GitHub Release 和最终 `main` Commit 精确一致。

## 发布命令

只在 Release PR 合并、发布内容与 `origin/main` 一致后执行：

```bash
release_commit="$(gh api repos/jiumem/forgeloop/commits/main --jq .sha)"
gh release create v4.2.0 \
  --repo jiumem/forgeloop \
  --target "$release_commit" \
  --title "Forgeloop 4.2.0" \
  --notes-file docs/releases/4.2.0-release-notes.md \
  --latest
```

Tag 必须指向 Release PR 合并后的最终 `main` Commit；不得从本地候选提交、未合并分支或旧验证 Head 发布。
