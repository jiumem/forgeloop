# Forgeloop 4.1.0 发布候选

状态：源码门禁、authenticated Agent evaluation 与本地候选安装回读已通过，并已取得创建 Release PR、合并、Tag 和 GitHub Release 的明确授权。只能从 Release PR 合并后的最终 `main` Commit 发布。

## 发布范围

- Ticket Coder、Spec Reviewer 与 Standards Reviewer 使用统一交付价值函数。
- Spec Reviewer 广泛检查，但只有满足必要性链条且具有可观察失败的 Finding 才阻塞。
- Coder 独立诊断 Reviewer Finding，并以最小完整修复为默认动作。
- 上游 Skills 固定版本升级到 `v1.2.3`，选择性吸收安全、YAGNI、Harness、TDD、Prototype 和 Wayfinder 改进。
- Grilling 每轮最多五个独立问题，支持批量接受，并在最小完整设计形成后停止。
- 不集成 Wizard、自动研究代理、自动研究分支和额外入口。
- 不新增 Skill、Event、持久化状态、Tracker Item 类型或 parser。

## 验收标准

- 入口：Manifest、README 和发布配置统一回读为 `4.1.0`。
- 核心行为：价值函数、Finding 必要性、Grilling 上限及上游适配均有合同测试和 Agent evaluation 覆盖。
- 输出状态：源码与安装缓存内容一致，缓存只包含插件允许的顶层目录。
- 错误处理：版本漂移、未映射上游文件、安装缓存差异和 Agent 语义偏差必须使门禁失败并给出可定位输出。
- 关键边界：不扩张 Reviewer 正面职责，不自动创建研究代理、分支、提交或 Tracker 记录，不引入新状态。
- 发布验证：Release PR 合并后，Tag、GitHub Release 和最终 `main` Commit 精确一致。

## 发布命令

只在 Release PR 合并、发布内容与 `origin/main` 一致后执行：

```bash
release_commit="$(gh api repos/jiumem/forgeloop/commits/main --jq .sha)"
gh release create v4.1.0 \
  --repo jiumem/forgeloop \
  --target "$release_commit" \
  --title "Forgeloop 4.1.0" \
  --notes-file docs/releases/4.1.0-release-notes.md \
  --latest
```

Tag 必须指向 Release PR 合并后的最终 `main` Commit；不得从本地候选提交、未合并分支或旧验证 Head 发布。
