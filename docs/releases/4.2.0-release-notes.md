# Forgeloop 4.2.0

Forgeloop 4.2.0 收紧了 `$spec-standards-review` 的自动选择边界。双轴审查仍保留在正式的变更审查和 `run-initiative` 交付门禁中，但普通实现完成后的自检不再轻易启动两个独立 Reviewer。

## 恢复固定点变更审查语义

- `spec-standards-review` 的 Frontmatter description 恢复为上游的审查契约：审查必须围绕一个固定点之后的变更，明确说明 Standards 与 Spec 两轴，以及并行子代理的成本；
- 模型现在优先在用户要求审查分支、PR、进行中的变更或“review since X”时加载该 Skill，而不是因为某段已实现代码看起来“需要审查”；
- `$run-initiative` 的隐式调用能力保持不变。它在 Candidate 的 Base/Head 冻结后本来就要求两个只读 Reviewer 审查同一个固定 Commit 范围，因此仍处于新描述的正向范围内；
- `allow_implicit_invocation` 继续为 `true`，没有把双轴审查错误地降级为只能由用户手工点名的能力。

## 兼容性

- 显式调用 `$spec-standards-review` 后，既有的固定范围、快照范围、Spec 缺失和 Standards-only 处理规则保持可用；
- 仅凭“实现已经完成”“检查一下代码”或“检查单个文件”不再是自动启动并行双轴审查的承诺；
- 不新增或迁移 Skill、用户入口、Event、Tracker Item 类型、持久化状态或 parser。

## 验证

- 上游同步、集中 Skill 元数据、Skill UI 元数据与 Release Validator；
- 双轴审查路由评测：PR、`review since` 与 `run-initiative` 冻结 Commit 范围应加载；普通实现自检和无审查请求的单文件检查不应加载；
- 全量 Python 测试、Runtime Contract、Fixture、Skill Creator Quick Validation 和 Plugin Validator；
- Release PR 合并后的最终 `main` Commit、`v4.2.0` Tag 与 GitHub Release 精确绑定。
